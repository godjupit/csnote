## 1. 建表：实体完整性、参照完整性与用户定义完整性

来源：改编自书第 48～49 页习题 6（PDF 第 63～64 页）及第 50～51 页综合题①（PDF 第 65～66 页），对应 PPT 第 8～39 页。

要建立部门表 Department(dno, dname) 和员工表 Employee(eid, ename, age, job, salary, dno)。
dno 是部门编号，dname 是部门名称；eid、ename、age、job、salary 分别是员工编号、姓名、年龄、职称和工资。
部门编号和员工编号分别作为各自表的主码。部门名称不能为空，也不能重复；员工姓名不能为空。
年龄不能为空，只能在 18～65 之间；职称不能为空，只能是“讲师”“副教授”或“教授”；工资不能为空，且不能小于 0。
员工必须属于一个已经存在的部门。另外，教授的工资不能低于 4000，其他职称没有这一最低工资要求。
请写出两张表的建表语句，并指出其中哪些约束属于实体完整性、参照完整性和用户定义完整性。
再说明“教授工资至少 4000”为什么要同时检查职称和工资，为什么不能只写 CHECK(salary >= 4000)。
```sql
CREATE TABLE department (
    dno INT PRIMARY KEY,
    dname CHAR(30) NOT NULL UNIQUE
);

CREATE TABLE employee (
    eid INT PRIMARY KEY,
    ename CHAR(30) NOT NULL,
    age INT NOT NULL CHECK (age BETWEEN 18 AND 65),
    job VARCHAR(20) NOT NULL
        CHECK (job IN ('讲师', '副教授', '教授')),
    salary NUMERIC(10, 2) NOT NULL CHECK (salary >= 0),
    dno INT NOT NULL,

    FOREIGN KEY (dno) REFERENCES department(dno),

    CHECK (job <> '教授' OR salary >= 4000)
);
```
PRIMARY KEY是实体完整性，
FOREIGN KEY (dno) REFERENCES department(dno)是参完整性
dname NOT NULL UNIQUE   这些都是用户定义的完整性

 NOT NULL：必须填写部门              → 用户定义完整性
FOREIGN KEY：填写的部门必须真实存在   → 参照完整性


## 2. 外码：哪些操作会破坏参照完整性

来源：依据书第 48～49 页习题 5、7（PDF 第 63～64 页）及第 51～53 页综合题②（PDF 第 66～68 页）改编，对应 PPT 第 20～26 页。

部门表 Department(dno) 有 D1、D2 两个部门，dno 是主码。
员工表 Employee(eid, dno) 中，eid 是主码，dno 是参照部门编号的外码，可以为空。
目前三名员工的记录是（E1，D1）、（E2，D1）、（E3，D2）。下面每次操作都从这份初始数据开始，不连续执行。
请先判断：新增员工（E4，D9），或把 E1 的部门改为 D9，能否成功？
再考虑删除部门 D1：如果外码分别使用 ON DELETE NO ACTION、ON DELETE CASCADE、ON DELETE SET NULL，部门和员工记录各会怎样变化？
接着考虑把部门编号 D1 改为 D8：如果分别使用 ON UPDATE NO ACTION、ON UPDATE CASCADE、ON UPDATE SET NULL，两个表各会怎样变化？
最后回答：如果员工的部门编号还要求 NOT NULL，置空操作能否成功？只删除员工 E1，会不会违反本题的外码约束？请说明原因。

### 参考答案

本题中，Employee 是参照关系（持有外码），Department 是被参照关系（部门编号被引用）。每种情况都从下面的数据重新开始：

```text
部门：D1、D2
员工：(E1, D1)、(E2, D1)、(E3, D2)
```

**1. 新增员工或修改员工部门**

- 新增（E4，D9）：失败。部门表没有 D9，员工不能引用一个不存在的部门。
- 把 E1 的部门改为 D9：失败，原因相同。操作失败后，原数据保持不变。

**2. 删除部门 D1**

真正执行的删除语句相同，区别在于外码事先定义了哪种处理策略：

```sql
DELETE FROM Department WHERE dno = 'D1';
```

| 外码策略 | 操作结果 | 操作后的部门 | 操作后的员工 |
| --- | --- | --- | --- |
| ON DELETE NO ACTION | 有员工引用 D1，拒绝删除 | D1、D2 | （E1，D1）、（E2，D1）、（E3，D2） |
| ON DELETE CASCADE | 删除 D1，并删除引用它的员工整行 | D2 | （E3，D2） |
| ON DELETE SET NULL | 删除 D1，员工保留，把其部门编号置空 | D2 | （E1，NULL）、（E2，NULL）、（E3，D2） |

记法：NO ACTION 是“有人引用就不让删”；CASCADE 是“相关员工一起删”；SET NULL 是“员工留下，清空部门编号”。这些策略写在员工表的外码定义上，处理的是被引用部门删除后，员工记录怎么办。

**3. 把部门编号 D1 改为 D8**

```sql
UPDATE Department SET dno = 'D8' WHERE dno = 'D1';
```

| 外码策略 | 操作结果 | 操作后的部门 | 操作后的员工 |
| --- | --- | --- | --- |
| ON UPDATE NO ACTION | 有员工引用原编号 D1，拒绝修改 | D1、D2 | （E1，D1）、（E2，D1）、（E3，D2） |
| ON UPDATE CASCADE | 部门改为 D8，员工的对应外码也改为 D8 | D8、D2 | （E1，D8）、（E2，D8）、（E3，D2） |
| ON UPDATE SET NULL | 部门改为 D8，把原来引用 D1 的员工部门编号置空 | D8、D2 | （E1，NULL）、（E2，NULL）、（E3，D2） |

注意：ON UPDATE CASCADE 修改的是员工的部门编号，不是删除员工；ON DELETE CASCADE 才会在本题中删除对应员工整行。

**4. 员工部门编号还要求 NOT NULL 时**

SET NULL 不能成功完成，因为把部门编号设为 NULL 会违反非空约束。本题中，删除 D1 或将 D1 改为 D8 的整条操作因此失败，两个表都保持初始数据，不会出现“部门已经删了、员工却没有处理”的一半结果。

**5. 只删除员工 E1**

不会违反这条外码约束。删除后，部门仍是 D1、D2，员工剩下（E2，D1）、（E3，D2），两个非空部门编号都能在部门表中找到。删除参照表的一条引用，不会让剩余员工引用不存在的部门。

## 4. 读触发器：事件、条件、动作与 OLD／NEW

来源：改编自 PPT 第 51～57 页的成绩修改日志例题。

选课表 SC(sno, cno, grade) 记录学号、课程号和成绩，以（sno，cno）为主码，成绩可以为空。
日志表 SC_Log(sno, cno, old_grade, new_grade) 用来保存成绩修改前后的值。
请阅读下面的触发器，指出：它在什么操作发生时触发，是操作前还是操作后，满足什么条件才记录日志，记录到哪里。
再解释 OldTuple 和 NewTuple 分别表示什么。
现在一条 UPDATE 修改了 3 行成绩：60 改为 75，80 改为 85，NULL 改为 90。
请判断哪几行会记录日志，写出日志中的旧成绩和新成绩，并说明旧成绩为 NULL 时，WHEN 条件能否成立。

```sql
CREATE TRIGGER Grade_Change_Log
AFTER UPDATE OF grade ON SC
REFERENCING OLD ROW AS OldTuple
            NEW ROW AS NewTuple
FOR EACH ROW
WHEN (NewTuple.grade >= OldTuple.grade + 10)
    INSERT INTO SC_Log(sno, cno, old_grade, new_grade)
    VALUES (OldTuple.sno, OldTuple.cno,
            OldTuple.grade, NewTuple.grade);
```

## 6. 行级与语句级触发器：执行次数和失败处理

来源：依据 PPT 第 54、56、58、61 页自编，采用课件中的新插入行集合 Delta。

学生表 Student(sno, sname) 以学号 sno 为主码。
日志表 StudentInsertLog(numbers) 用来记录每条 INSERT 新增了多少名学生。下面是课件格式的语句级触发器。
如果一条 INSERT 成功插入 3 名学生，触发动作执行几次，日志增加几行，numbers 是多少？
如果换成连续执行 3 条 INSERT，每条插入 1 名学生，日志又会怎样？
再假设表上还有一个没有 WHEN 条件的 AFTER INSERT 行级触发器：一条语句插入 3 行时，它执行几次？
如果一条 INSERT 成功执行，但实际插入 0 行，行级和语句级触发动作分别执行几次？
最后说明 BEFORE 触发器、原始插入操作、AFTER 触发器的执行顺序。
如果某次触发动作失败，本次语句已做的数据修改和日志修改应怎样处理？按课件的整体撤销规则回答，不考虑程序捕获异常的特殊情况。

```sql
CREATE TRIGGER Student_Count
AFTER INSERT ON Student
REFERENCING NEW TABLE AS Delta
FOR EACH STATEMENT
    INSERT INTO StudentInsertLog(numbers)
    SELECT COUNT(*) FROM Delta;
```
