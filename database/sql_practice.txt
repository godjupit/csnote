# 一、SQL 查询（20 道）

## 基础筛选、日期与排序

思路：WHERE 先筛行，再选列、排序和取前 N 条；日期用“>= 起点且 < 下一段起点”。

### SQL 1：模糊查询与排序（原第1组第1题）

查询 `part` 表中，品牌 `p_brand` 以 `Brand#3` 开头、类型 `p_type` 包含 `BRASS` 的商品。
显示商品编号 `p_partkey`、名称 `p_name`、品牌 `p_brand`、类型 `p_type` 和尺寸 `p_size`，
按尺寸 `p_size` 降序、商品编号 `p_partkey` 升序排列。

答案：

```sql
SELECT p_partkey, p_name, p_brand, p_type, p_size
FROM part
WHERE p_brand LIKE 'Brand#3%'
  AND p_type LIKE '%BRASS%'
ORDER BY p_size DESC, p_partkey ASC;
```

### SQL 2：日期筛选与前 N 条记录（原第1组第3题）

查询 `orders` 表中，下单日期 `o_orderdate` 在 1995 年内且优先级 `o_orderpriority` 包含
`URGENT` 的订单。显示订单编号 `o_orderkey`、日期 `o_orderdate`、优先级 `o_orderpriority`
 和总金额 `o_totalprice`，按总金额 `o_totalprice` 降序排列，只显示前 10 条。

答案：

```sql
SELECT o_orderkey, o_orderdate, o_orderpriority, o_totalprice
FROM orders
WHERE o_orderdate >= DATE '1995-01-01'
  AND o_orderdate < DATE '1996-01-01'
  AND o_orderpriority LIKE '%URGENT%'
ORDER BY o_totalprice DESC, o_orderkey
LIMIT 10;
```

## 分组统计与 HAVING

思路：先用 WHERE 限定统计范围，再按对象分组，用 HAVING 筛选数量或平均值。

### SQL 3：分组统计与分组筛选（原第1组第2题）

查询 `customer` 表中各市场区域 `c_mktsegment` 的客户数量（统计客户编号 `c_custkey`）和平
均账户余额（对 `c_acctbal` 求平均值）。显示市场区域及以上两项统计结果。只保留客户数量超
过 290 的区域，按平均账户余额降序排列。

答案：

```sql
SELECT c_mktsegment, COUNT(*) AS customer_count,
       AVG(c_acctbal) AS avg_balance
FROM customer
GROUP BY c_mktsegment
HAVING COUNT(*) > 290
ORDER BY avg_balance DESC;
```

### SQL 4：连接、聚合与 HAVING（原第1组第7题）

查询每个国家的客户数量和平均账户余额。连接 `nation` 和 `customer`，显示国家名称 `n_name`
、客户数量（统计客户编号 `c_custkey`）及平均账户余额（对 `c_acctbal` 求平均值），只保留
平均账户余额大于 4000 的国家。

连接字段：`nation.n_nationkey` 与 `customer.c_nationkey` 对应。

答案：

```sql
SELECT n.n_name, COUNT(c.c_custkey) AS customer_count,
       AVG(c.c_acctbal) AS avg_balance
FROM nation n
JOIN customer c ON c.c_nationkey = n.n_nationkey
GROUP BY n.n_nationkey, n.n_name
HAVING AVG(c.c_acctbal) > 4000;
```

### SQL 5：分组统计与筛选：订单较多的大额客户（原第5组第9题）

查询 1995 年下单至少 5 笔、且这些订单平均总金额大于 150000 的客户，
使用 customer 和 orders，以订单日期（o_orderdate）确定年份，
订单金额为 o_totalprice，客户与订单通过 c_custkey、o_custkey 关联。
结果显示客户编号（c_custkey）、名称（c_name）、当年订单数量（order_count）
和当年平均订单金额（avg_amount），按平均订单金额降序、客户编号升序排列。

答案：

```sql
SELECT c.c_custkey, c.c_name, COUNT(o.o_orderkey) AS order_count,
       AVG(o.o_totalprice) AS avg_amount
FROM customer c
JOIN orders o ON o.o_custkey = c.c_custkey
WHERE o.o_orderdate >= DATE '1995-01-01'
  AND o.o_orderdate < DATE '1996-01-01'
GROUP BY c.c_custkey, c.c_name
HAVING COUNT(o.o_orderkey) >= 5
   AND AVG(o.o_totalprice) > 150000
ORDER BY avg_amount DESC, c.c_custkey;
```

## 自连接与去除重复组合

思路：同表取两个别名，用编号大小关系同时排除自身与反向重复配对。

### SQL 6：自连接与去除重复组合（原第1组第9题）

在 `customer` 表中查询国家编号 `c_nationkey` 相同、且市场区域 `c_mktsegment` 不同的客户
对。显示两个客户的编号 `c_custkey`、名称 `c_name` 和共同的国家编号 `c_nationkey`。要求不
能将客户与自身配对，同一对客户只出现一次，例如出现 `(1, 2)` 后不能再出现 `(2, 1)`。

答案：

```sql
SELECT c1.c_custkey AS customer1_id, c1.c_name AS customer1_name,
       c2.c_custkey AS customer2_id, c2.c_name AS customer2_name,
       c1.c_nationkey
FROM customer c1
JOIN customer c2 ON c2.c_nationkey = c1.c_nationkey
               AND c1.c_custkey < c2.c_custkey
WHERE c1.c_mktsegment <> c2.c_mktsegment;
```

## 普通子查询与相关子查询

思路：全表平均值固定不变；“同国同类”的平均值要通过字段关联当前客户。

### SQL 7：高于所有订单平均金额的订单（原第2组第1题）

表：orders

查询订单总金额 o_totalprice 高于整张订单表平均总金额的订单。

显示：
  订单编号 o_orderkey
  客户编号 o_custkey
  订单总金额 o_totalprice

先想：检查不同订单时，内层计算的平均值需要变化吗？

答案：

```sql
SELECT o.o_orderkey, o.o_custkey, o.o_totalprice
FROM orders o
WHERE o.o_totalprice > (
    SELECT AVG(o_totalprice)
    FROM orders
);
```

### SQL 8：相关子查询：高于同国同类客户平均余额（原第5组第6题）

查询账户余额（c_acctbal）高于本国、同一市场区域内所有客户平均账户余额的客户，
使用 customer，国家由 c_nationkey 确定，市场区域由 c_mktsegment 确定，
计算平均值时包含当前客户本人。
结果显示客户编号（c_custkey）、名称（c_name）、国家编号（c_nationkey）、
市场区域（c_mktsegment）和账户余额（c_acctbal），按账户余额降序排列。

答案：

```sql
SELECT c.c_custkey, c.c_name, c.c_nationkey,
       c.c_mktsegment, c.c_acctbal
FROM customer c
WHERE c.c_acctbal > (
    SELECT AVG(c1.c_acctbal)
    FROM customer c1
    WHERE c1.c_nationkey = c.c_nationkey
      AND c1.c_mktsegment = c.c_mktsegment
)
ORDER BY c.c_acctbal DESC;
```

## 存在与不存在

思路：至少一条用 EXISTS，一条也没有用 NOT EXISTS；内层要关联当前客户并限定日期。

### SQL 9：存在与不存在的子查询（原第1组第8题）

分别编写两条 SQL：

1. 查询至少下过一笔订单的客户，显示客户编号 `c_custkey` 和名称 `c_name`，每个客户只出现
一次。
2. 查询从未下过订单的客户，显示客户编号 `c_custkey` 和名称 `c_name`。

涉及 `customer` 和 `orders` 两张表，客户编号 `customer.c_custkey` 与订单所属客户编号
`orders.o_custkey` 对应。尝试分别使用 `EXISTS` 和 `NOT EXISTS`。

答案：

```sql
-- 至少下过一笔订单
SELECT c.c_custkey, c.c_name
FROM customer c
WHERE EXISTS (
    SELECT 1
    FROM orders o
    WHERE o.o_custkey = c.c_custkey
);

-- 从未下过订单
SELECT c.c_custkey, c.c_name
FROM customer c
WHERE NOT EXISTS (
    SELECT 1
    FROM orders o
    WHERE o.o_custkey = c.c_custkey
);
```

### SQL 10：七月活跃、八月沉默的客户（原第4组第3题）

查询 1996 年 7 月至少下过两笔订单、但同年 8 月没有下过任何订单的客户，
使用 customer 和 orders，以订单日期（o_orderdate）确定月份。
结果显示客户编号（c_custkey）、名称（c_name）、7 月订单数量（july_count）
和 7 月订单总金额合计（july_amount），按 7 月订单总金额合计降序排列。
客户与订单通过 c_custkey、o_custkey 关联。

答案：

```sql
SELECT c.c_custkey, c.c_name, COUNT(*) AS july_count,
       SUM(o.o_totalprice) AS july_amount
FROM customer c
JOIN orders o ON o.o_custkey = c.c_custkey
WHERE o.o_orderdate >= DATE '1996-07-01'
  AND o.o_orderdate < DATE '1996-08-01'
  AND NOT EXISTS (
      SELECT 1
      FROM orders o1
      WHERE o1.o_custkey = c.c_custkey
        AND o1.o_orderdate >= DATE '1996-08-01'
        AND o1.o_orderdate < DATE '1996-09-01'
  )
GROUP BY c.c_custkey, c.c_name
HAVING COUNT(*) >= 2
ORDER BY july_amount DESC;
```

### SQL 11：存在与不存在：买过指定品牌但没买过另一品牌（原第5组第8题）

查询在 1995 年至少购买过一次 Brand#11 商品、但从未购买过 Brand#12 商品的客户，
两个品牌的购买记录都只检查 1995 年，允许购买其他品牌。
使用 customer、orders、lineitem 和 part，以订单日期（o_orderdate）确定年份，
品牌字段为 p_brand，结果显示客户编号（c_custkey）、名称（c_name），
每个客户只出现一次，按客户编号升序排列。
关联字段依次为 c_custkey 与 o_custkey、o_orderkey 与 l_orderkey、
l_partkey 与 p_partkey。

答案：

```sql
SELECT c.c_custkey, c.c_name
FROM customer c
WHERE EXISTS (
    SELECT 1
    FROM orders o
    JOIN lineitem l ON l.l_orderkey = o.o_orderkey
    JOIN part p ON p.p_partkey = l.l_partkey
    WHERE o.o_custkey = c.c_custkey
      AND o.o_orderdate >= DATE '1995-01-01'
      AND o.o_orderdate < DATE '1996-01-01'
      AND p.p_brand = 'Brand#11'
)
AND NOT EXISTS (
    SELECT 1
    FROM orders o1
    JOIN lineitem l1 ON l1.l_orderkey = o1.o_orderkey
    JOIN part p1 ON p1.p_partkey = l1.l_partkey
    WHERE o1.o_custkey = c.c_custkey
      AND o1.o_orderdate >= DATE '1995-01-01'
      AND o1.o_orderdate < DATE '1996-01-01'
      AND p1.p_brand = 'Brand#12'
)
ORDER BY c.c_custkey;
```

## 左连接与零记录

思路：从需要全部保留的表出发，右表日期条件放在 ON；数量数右表主码，空金额转成 0。

### SQL 12：连接与零记录：保留所有国家的年度订单统计（原第5组第3题）

统计每个国家的客户在 1995 年下的订单数量及订单总金额合计，
使用 nation、customer 和 orders，以订单日期（o_orderdate）确定年份，
要求保留 nation 中所有国家，没有客户或当年没有订单的国家，
订单数量和订单总金额合计都显示为 0。
结果显示国家编号（n_nationkey）、国家名称（n_name）、订单数量（order_count）
和订单总金额合计（total_amount），按国家编号升序排列。
关联字段为 n_nationkey 与 c_nationkey、c_custkey 与 o_custkey，
订单编号为 o_orderkey，订单总金额为 o_totalprice。

答案：

```sql
SELECT n.n_nationkey, n.n_name, COUNT(o.o_orderkey) AS order_count,
       COALESCE(SUM(o.o_totalprice), 0) AS total_amount
FROM nation n
LEFT JOIN customer c ON c.c_nationkey = n.n_nationkey
LEFT JOIN orders o ON o.o_custkey = c.c_custkey
                  AND o.o_orderdate >= DATE '1995-01-01'
                  AND o.o_orderdate < DATE '1996-01-01'
GROUP BY n.n_nationkey, n.n_name
ORDER BY n.n_nationkey;
```

## 去重与计数单位

思路：连接明细后，一行不再代表一笔订单；订单、商品、供应商分别按编号去重计数。

### SQL 13：去重与计数单位：多订单、多商品、多供应商的客户（原第5组第4题）

查询在 1995 年至少下过 3 笔订单、购买过至少 5 种不同商品，
且这些商品的实际供货明细涉及至少 2 个不同供应商的客户。
使用 customer、orders 和 lineitem，以订单日期（o_orderdate）确定年份，
订单按 o_orderkey 去重计数，商品按 l_partkey 去重计数，
供应商按 l_suppkey 去重计数，同一商品在多笔订单中出现仍只算一种。
结果显示客户编号（c_custkey）、名称（c_name）、不同订单数量（order_count）、
不同商品数量（part_count）和不同供应商数量（supplier_count），
按订单数量降序、客户编号升序排列。
客户与订单通过 c_custkey、o_custkey 关联，订单与明细通过 o_orderkey、l_orderkey 关联；
本题只统计至少包含一条明细的订单。

答案：

```sql
SELECT c.c_custkey, c.c_name,
       COUNT(DISTINCT o.o_orderkey) AS order_count,
       COUNT(DISTINCT l.l_partkey) AS part_count,
       COUNT(DISTINCT l.l_suppkey) AS supplier_count
FROM customer c
JOIN orders o ON o.o_custkey = c.c_custkey
JOIN lineitem l ON l.l_orderkey = o.o_orderkey
WHERE o.o_orderdate >= DATE '1995-01-01'
  AND o.o_orderdate < DATE '1996-01-01'
GROUP BY c.c_custkey, c.c_name
HAVING COUNT(DISTINCT o.o_orderkey) >= 3
   AND COUNT(DISTINCT l.l_partkey) >= 5
   AND COUNT(DISTINCT l.l_suppkey) >= 2
ORDER BY order_count DESC, c.c_custkey;
```

## 多层聚合与平均水平

思路：先明确每个对象的统计量，再求平均；本国人均值的分母必须包含零订单客户。

### SQL 14：客户数量超过平均水平的市场区域（原第2组第7题）

在 customer 表中，哪些市场区域的客户数量超过所有市场区域的平均客户数量，
结果显示市场区域（c_mktsegment）、客户数量（命名为 customer_count），
并按客户数量降序排列。

答案：

```sql
SELECT c_mktsegment, COUNT(*) AS customer_count
FROM customer
GROUP BY c_mktsegment
HAVING COUNT(*) > (
    SELECT AVG(t.customer_count)
    FROM (
        SELECT COUNT(*) AS customer_count
        FROM customer
        GROUP BY c_mktsegment
    ) t
)
ORDER BY customer_count DESC;
```

### SQL 15：高于本国平均年度消费额的客户（原第4组第2题）

查询 1995 年消费总额高于本国客户平均年度消费额的客户，
使用 customer 和 orders，以订单日期（o_orderdate）确定年份，
消费总额为订单总金额（o_totalprice）的合计。
计算本国平均值时，应包含该国所有客户，没有在 1995 年下单的客户按 0 计算。
结果显示客户编号（c_custkey）、名称（c_name）、国家编号（c_nationkey）
和年度消费总额（year_amount），按年度消费总额降序排列。
客户与订单通过 c_custkey、o_custkey 关联。

答案：

```sql
SELECT c.c_custkey, c.c_name, c.c_nationkey,
       COALESCE(SUM(o.o_totalprice), 0) AS year_amount
FROM customer c
LEFT JOIN orders o ON o.o_custkey = c.c_custkey
                  AND o.o_orderdate >= DATE '1995-01-01'
                  AND o.o_orderdate < DATE '1996-01-01'
GROUP BY c.c_custkey, c.c_name, c.c_nationkey
HAVING COALESCE(SUM(o.o_totalprice), 0) > (
    SELECT COALESCE(SUM(o1.o_totalprice), 0)
           / COUNT(DISTINCT c1.c_custkey)
    FROM customer c1
    LEFT JOIN orders o1 ON o1.o_custkey = c1.c_custkey
                       AND o1.o_orderdate >= DATE '1995-01-01'
                       AND o1.o_orderdate < DATE '1996-01-01'
    WHERE c1.c_nationkey = c.c_nationkey
)
ORDER BY year_amount DESC;
```

### SQL 16：多层聚合：订单数超过本国客户平均水平（原第5组第5题）

查询 1995 年订单数量大于本国客户当年平均订单数量的客户，
使用 customer 和 orders，以订单日期（o_orderdate）确定年份，
国家由 c_nationkey 确定；计算本国平均值时包含本国所有客户，
当年没有订单的客户按 0 单计算，当前客户本人也参与平均值计算。
结果显示客户编号（c_custkey）、名称（c_name）、国家编号（c_nationkey）
和当年订单数量（order_count），按国家编号升序、订单数量降序排列。
客户与订单通过 c_custkey、o_custkey 关联。

答案：

```sql
SELECT c.c_custkey, c.c_name, c.c_nationkey,
       COUNT(o.o_orderkey) AS order_count
FROM customer c
LEFT JOIN orders o ON o.o_custkey = c.c_custkey
                  AND o.o_orderdate >= DATE '1995-01-01'
                  AND o.o_orderdate < DATE '1996-01-01'
GROUP BY c.c_custkey, c.c_name, c.c_nationkey
HAVING COUNT(o.o_orderkey) > (
    SELECT COUNT(o1.o_orderkey) * 1.0 / COUNT(DISTINCT c1.c_custkey)
    FROM customer c1
    LEFT JOIN orders o1 ON o1.o_custkey = c1.c_custkey
                       AND o1.o_orderdate >= DATE '1995-01-01'
                       AND o1.o_orderdate < DATE '1996-01-01'
    WHERE c1.c_nationkey = c.c_nationkey
)
ORDER BY c.c_nationkey, order_count DESC;
```

## 组内最值与并列

思路：先按客户或供应商汇总，再与同组全部汇总值比较；>= ALL 保留并列，零订单客户也参与比较。

### SQL 17：每个国家的销售冠军（原第4组第4题）

查询 1996 年 7 月每个国家销售额最高的供应商，使用 nation、supplier 和 lineitem，
以发货日期（l_shipdate）确定月份，按供应商所属国家分组比较，
销售额为 l_extendedprice * (1 - l_discount) 的合计。
结果显示国家名称（n_name）、供应商编号（s_suppkey）、名称（s_name）
和当月销售额（sales_amount）；同一国家如有并列冠军，全部显示，
当月没有销售记录的国家不显示。
国家与供应商通过 n_nationkey、s_nationkey 关联，
供应商与明细通过 s_suppkey、l_suppkey 关联。

答案：

```sql
SELECT n.n_name, s.s_suppkey, s.s_name,
       SUM(l.l_extendedprice * (1 - l.l_discount)) AS sales_amount
FROM nation n
JOIN supplier s ON s.s_nationkey = n.n_nationkey
JOIN lineitem l ON l.l_suppkey = s.s_suppkey
WHERE l.l_shipdate >= DATE '1996-07-01'
  AND l.l_shipdate < DATE '1996-08-01'
GROUP BY n.n_nationkey, n.n_name, s.s_suppkey, s.s_name
HAVING SUM(l.l_extendedprice * (1 - l.l_discount)) >= ALL (
    SELECT SUM(l1.l_extendedprice * (1 - l1.l_discount))
    FROM supplier s1
    JOIN lineitem l1 ON l1.l_suppkey = s1.s_suppkey
    WHERE s1.s_nationkey = n.n_nationkey
      AND l1.l_shipdate >= DATE '1996-07-01'
      AND l1.l_shipdate < DATE '1996-08-01'
    GROUP BY s1.s_suppkey
)
ORDER BY n.n_name, s.s_suppkey;
```

### SQL 18：本国订单数量最多的客户（原第4组第8题）

查询下单数量大于等于本国其他所有客户下单数量的客户，使用 customer 和 orders，
客户所属国家由 c_nationkey 确定，订单数量通过统计订单编号（o_orderkey）得到，
没有下过订单的客户按 0 计算；同一国家如有并列最多的客户，全部显示。
结果显示客户编号（c_custkey）、名称（c_name）、国家编号（c_nationkey）
和订单数量（order_count），按国家编号升序、客户编号升序排列。
客户与订单通过 c_custkey、o_custkey 关联。

答案：

```sql
SELECT c.c_custkey, c.c_name, c.c_nationkey,
       COUNT(o.o_orderkey) AS order_count
FROM customer c
LEFT JOIN orders o ON o.o_custkey = c.c_custkey
GROUP BY c.c_custkey, c.c_name, c.c_nationkey
HAVING COUNT(o.o_orderkey) >= ALL (
    SELECT COUNT(o1.o_orderkey)
    FROM customer c1
    LEFT JOIN orders o1 ON o1.o_custkey = c1.c_custkey
    WHERE c1.c_nationkey = c.c_nationkey
    GROUP BY c1.c_custkey
)
ORDER BY c.c_nationkey, c.c_custkey;
```

## 全称条件

思路：“每笔都达标”可检查最低金额是否达标；内连接保证至少有一笔订单。

### SQL 19：全称条件：每笔订单都达到金额要求的客户（原第5组第1题）

查询在 1995 年至少下过一笔订单，且当年每笔订单总金额（o_totalprice）
都不低于 100000 的客户，其他年份的订单不影响判断。
使用 customer 和 orders，以订单日期（o_orderdate）确定年份，
客户与订单通过 c_custkey、o_custkey 关联。
结果显示客户编号（c_custkey）、名称（c_name）
和当年订单数量（order_count），按订单数量降序、客户编号升序排列。

答案：

```sql
SELECT c.c_custkey, c.c_name, COUNT(*) AS order_count
FROM customer c
JOIN orders o ON o.o_custkey = c.c_custkey
WHERE o.o_orderdate >= DATE '1995-01-01'
  AND o.o_orderdate < DATE '1996-01-01'
GROUP BY c.c_custkey, c.c_name
HAVING MIN(o.o_totalprice) >= 100000
ORDER BY order_count DESC, c.c_custkey;
```

## 集合包含

思路：双重 NOT EXISTS 表示“没有目标商品被漏掉”；目标集合为空时也要正确处理。

### SQL 20：集合包含：供应了指定供应商的全部商品（原第5组第2题）

查询供应了编号为 1 的供应商所供应的全部商品的其他供应商，
使用 supplier 和 partsupp；允许候选供应商额外供应其他商品，
不比较供应成本和库存，只比较商品编号（ps_partkey）是否全部覆盖。
结果显示供应商编号（s_suppkey）、名称（s_name），每个供应商只出现一次，
按供应商编号升序排列，编号为 1 的供应商本人不显示。
供应商与供货记录通过 s_suppkey、ps_suppkey 关联；
如果编号为 1 的供应商没有任何供货记录，则其他所有供应商均满足条件。

答案：

```sql
SELECT s.s_suppkey, s.s_name
FROM supplier s
WHERE s.s_suppkey <> 1
  AND NOT EXISTS (
      SELECT 1
      FROM partsupp p1
      WHERE p1.ps_suppkey = 1
        AND NOT EXISTS (
            SELECT 1
            FROM partsupp p2
            WHERE p2.ps_suppkey = s.s_suppkey
              AND p2.ps_partkey = p1.ps_partkey
        )
  )
ORDER BY s.s_suppkey;
```

# 二、关系代数（15 道）

公共表：Student(Sno,Sname,Smajor,Sage)、Course(Cno,Cname,Cpno)、SC(Sno,Cno,Grade)。
Student、Course 的主码分别是 Sno、Cno；SC 的主码为 (Sno,Cno)，分别参照学生和课程。

供前两题使用的学生数据：
S1，张明，计算机，20
S2，李红，计算机，21
S3，王强，数学，20
S4，张明，计算机，20
S5，赵宁，物理，22

教师相关题使用 Teacher(Tno,Tname,Tage,Tsex)、Department(Dno,Dname,DTno)、Work(Tno,Dno,Year,Salary)。
DTno 是系主任教师号；Work 每名教师最多一条记录，可存在没有工作记录的教师和没有教师的系。

π：投影；σ：选择；⋈：自然连接；⋈条件：条件连接；÷：除；ρ：重命名；⟕、⟖：左、右外连接。
Student、SC、Course 的自然连接只按同名的 Sno、Cno 连接；表达式也可分步写中间结果。

## 选择、投影与连接

思路：选择筛行，投影取列并去重；跨表条件先连接，再筛选和投影。

### 关系代数 1：只取一列（原书写1）

查询学生中出现过哪些专业，只输出专业 Smajor。请写关系代数表达式，并根据公共数据列出结果。

答案：

```text
π_{Smajor}(Student)
```

结果：{计算机，数学，物理}。

### 关系代数 2：取两列并去重（原书写2）

查询学生的姓名和专业，只输出 Sname、Smajor。请写关系代数表达式，并判断两名同叫张明的计算机专业学生在结果中显示几行。

答案：

```text
π_{Sname,Smajor}(Student)
```

两名“张明，计算机”投影后合并为一行，整个结果共 4 行。

### 关系代数 3：先筛选，再取列（原书写4）

查询计算机专业且年龄不超过 20 岁的学生，只显示 Sno、Sname。请写关系代数表达式。

答案：

```text
π_{Sno,Sname}(σ_{Smajor='计算机' ∧ Sage<=20}(Student))
```

### 关系代数 4：两表连接（原书写5）

查询 C1 课程成绩大于等于 80 分的学生，显示 Sno、Sname、Grade。请写关系代数表达式。

答案：

```text
π_{Sno,Sname,Grade}(Student ⋈ σ_{Cno='C1' ∧ Grade>=80}(SC))
```

### 关系代数 5：三表连接（原书写6）

查询选修了课程名为“数据库”的学生，显示 Sno、Sname。请写关系代数表达式，不把“数据库”的课程号直接写死为 C1。

答案：

```text
π_{Sno,Sname}(Student ⋈ SC ⋈ σ_{Cname='数据库'}(Course))
```

## 交、并、差与不存在

思路：“同时”用交，“或”用并，“没有”从全部对象中减去符合条件的集合。

### 关系代数 6：同时满足两个条件：交（原书写7）

查询既选修 C1 又选修 C2 的学生，只输出 Sno。请使用交运算写关系代数表达式；一条 SC 记录只代表一个学生选一门课程。

答案：

```text
π_{Sno}(σ_{Cno='C1'}(SC)) ∩ π_{Sno}(σ_{Cno='C2'}(SC))
```

### 关系代数 7：至少满足一个条件：并（原书写8）

查询选修 C1 或 C2 的学生，只输出 Sno，选了两门的学生也只显示一次。请使用并运算写关系代数表达式。

答案：

```text
π_{Sno}(σ_{Cno='C1'}(SC)) ∪ π_{Sno}(σ_{Cno='C2'}(SC))
```

### 关系代数 8：没有选指定课程：差（原书写9）

查询没有选修 C1 的学生，只输出 Sno。请使用差运算，结果必须包括没有任何选课记录的学生。

答案：

```text
π_{Sno}(Student) − π_{Sno}(σ_{Cno='C1'}(SC))
```

从全部学生学号出发，才能保留没有任何选课记录的学生。

### 关系代数 9：没有任何选课记录（原书写10）

查询一门课也没有选的学生，显示 Sno、Sname。请写关系代数表达式。

答案：

```text
π_{Sno,Sname}(Student ⋈ (π_{Sno}(Student) − π_{Sno}(SC)))
```

## 除运算与集合包含

思路：先确定需要覆盖的目标集合，再用除运算找出全部覆盖者；多选其他课程不影响满足条件。

### 关系代数 10：选修全部课程：除（原书写11）

查询选修了 Course 表中全部课程的学生，只输出 Sno。请使用除运算，成绩高低不影响“已经选修”的判断。
Course 在本题数据中非空。

答案：

```text
π_{Sno,Cno}(SC) ÷ π_{Cno}(Course)
```

### 关系代数 11：包含另一名学生选的全部课程（原书写12）

查询至少选修了学生 S4 所选全部课程的其他学生，显示 Sno、Sname。允许多选其他课程，但不显示 S4 本人。
请使用除运算；本题 S4 至少选了一门课。

答案：

```text
T = π_{Cno}(σ_{Sno='S4'}(SC))
U = π_{Sno,Cno}(SC) ÷ T
结果 = π_{Sno,Sname}(σ_{Sno<>'S4'}(Student ⋈ U))
```

先确定 S4 的课程集合，再找覆盖该集合的学生，最后排除 S4 本人。

### 关系代数 12：用基本运算表示除（提高）（原书写23）

关系 R(X, Y) 和 S(Y) 中，X、Y 各表示一个属性，Y 的域相同，S 非空。请把 R÷S 改写成只使用投影、笛卡尔积和差的表达式。
允许给中间结果起名字，再按步骤组合。

答案：

```text
A = π_X(R)
B = (A × S) − R
结果 = A − π_X(B)
```

B 找出缺少的 (X,Y) 配对，再排除至少缺少一个目标 Y 的 X。

## 重命名与自连接

思路：把 Work 分成两个副本，先找出存在反例的教师，再从候选教师中排除。

### 关系代数 13：重命名与自连接：高于一组人的所有工资（原书写18）

查询工资严格高于 D1 系每位教师工资的教师，只输出 Tno。只比较有 Work 记录的教师，工资均非空，D1 系至少有一条 Work 记录。
请使用关系代数表达式，可以把 Work 重命名为两个副本，不使用聚集函数 MAX。

答案：

```text
W1 = ρ_{W1}(Work)
W2 = ρ_{W2}(Work)
Bad = π_{W1.Tno}(σ_{W2.Dno='D1' ∧ W1.Salary<=W2.Salary}(W1 × W2))
结果 = π_{Tno}(Work) − Bad
```

Bad 的单列属性重命名为 Tno 后再做差；它表示至少被 D1 某人工资追平或超过的教师。

## 左外连接与右外连接

思路：先确定必须保留哪一侧；未匹配的一侧补 NULL，最后投影题目要求的列。

### 关系代数 14：左外连接：保留全部教师（原书写19）

查询所有教师的姓名和所在系名称，显示 Tno、Tname、Dname。没有 Work 记录的教师也要出现，系名称显示 NULL。
请使用左外连接写关系代数表达式。

答案：

```text
π_{Teacher.Tno,Tname,Dname}(
  (Teacher ⟕_{Teacher.Tno=Work.Tno} Work)
  ⟕_{Work.Dno=Department.Dno} Department
)
```

连续左外连接，保留每名教师；没有工作记录时系名称为 NULL。

### 关系代数 15：右外连接：保留全部系（原书写20）

查询所有系及其教师，显示 Dno、Dname、Tname。没有教师的系也要出现，教师姓名显示 NULL。请使用右外连接写关系代数表达式；
教师可以暂时没有 Work 记录，但每条 Work 都参照存在的教师和系。

答案：

```text
π_{Department.Dno,Dname,Tname}(
  (Teacher ⋈_{Teacher.Tno=Work.Tno} Work)
  ⟖_{Work.Dno=Department.Dno} Department

```

Department 在右边，右外连接保留全部系；没有教师的系，教师姓名为 NULL。

# 三、触发器与存储过程典型练习（10 道，附参考答案）

本组使用 PostgreSQL。每题独立，所用表均为练习表，不修改前面的 TPC-H 数据。
触发器题需写出触发器函数和 CREATE TRIGGER；存储过程题需写出 CREATE PROCEDURE，
并给出一条 CALL 调用语句。以下表结构已给定，无需另写建表语句。
参考答案中，%TYPE 表示沿用已有表字段的类型；调用示例的编号需替换为实际数据。
使用 OUT 参数的存储过程答案适用于 PostgreSQL 14 及以上版本。

## 触发器（5 道）

### 触发器 1：插入、更新前自动修正工资

已知教师表 Teacher(Tno, Tname, Job, Salary)，字段分别表示教师号、姓名、职称和工资，
Tno 为主键，Job、Salary 均非空。编写 BEFORE INSERT OR UPDATE 行级触发器，
当新记录的职称 Job 为“教授”且工资 Salary 小于 4000 时，将新工资改为 4000，
其他情况保留输入值。请直接修改 NEW 中的工资，不在触发器中再次更新 Teacher 表。

参考答案：

```sql
CREATE OR REPLACE FUNCTION fix_teacher_salary()
RETURNS TRIGGER
LANGUAGE plpgsql
AS $$
BEGIN
    IF NEW.Job = '教授' AND NEW.Salary < 4000 THEN
        NEW.Salary := 4000;
    END IF;
    RETURN NEW;
END;
$$;

CREATE TRIGGER teacher_salary_before
BEFORE INSERT OR UPDATE ON Teacher
FOR EACH ROW
EXECUTE FUNCTION fix_teacher_salary();
```

BEFORE 行级触发器直接修改 NEW，RETURN NEW 将修正后的新行交给原操作保存。

### 触发器 2：成绩修改日志

已知选课表 SC(Sno, Cno, Grade)，以 (Sno, Cno) 为主键，Grade 允许为 NULL；
日志表 GradeLog(Sno, Cno, OldGrade, NewGrade, ChangedAt) 分别保存学号、课程号、
旧成绩、新成绩和修改时间。编写 AFTER UPDATE 行级触发器，仅当 Grade 的值实际变化时
向 GradeLog 插入一条日志；NULL 改为具体分数或具体分数改为 NULL 也算变化，
NULL 改为 NULL 不记日志，ChangedAt 使用当前时间。

参考答案：

```sql
CREATE OR REPLACE FUNCTION log_grade_change()
RETURNS TRIGGER
LANGUAGE plpgsql
AS $$
BEGIN
    INSERT INTO GradeLog(Sno, Cno, OldGrade, NewGrade, ChangedAt)
    VALUES (NEW.Sno, NEW.Cno, OLD.Grade, NEW.Grade, CURRENT_TIMESTAMP);
    RETURN NEW;
END;
$$;

CREATE TRIGGER sc_grade_after_update
AFTER UPDATE ON SC
FOR EACH ROW
WHEN (OLD.Grade IS DISTINCT FROM NEW.Grade)
EXECUTE FUNCTION log_grade_change();
```

IS DISTINCT FROM 可以比较 NULL：NULL 与具体分数不同，两个 NULL 相同。普通 <> 不能覆盖这些情况。

### 触发器 3：删除前保留旧记录

已知选课表 SC(Sno, Cno, Grade)，以 (Sno, Cno) 为主键；
归档表 SCArchive(Sno, Cno, Grade, DeletedAt) 用来保存被删除的选课记录，允许重复归档。
编写 DELETE 行级触发器，每删除一条 SC 记录，就将其学号、课程号、成绩和当前时间
保存到 SCArchive。请自行选择触发时机，并使用被删除行中的字段值。

参考答案：

```sql
CREATE OR REPLACE FUNCTION archive_deleted_sc()
RETURNS TRIGGER
LANGUAGE plpgsql
AS $$
BEGIN
    INSERT INTO SCArchive(Sno, Cno, Grade, DeletedAt)
    VALUES (OLD.Sno, OLD.Cno, OLD.Grade, CURRENT_TIMESTAMP);
    RETURN OLD;
END;
$$;

CREATE TRIGGER sc_archive_before_delete
BEFORE DELETE ON SC
FOR EACH ROW
EXECUTE FUNCTION archive_deleted_sc();
```

选择 BEFORE DELETE，用 OLD 读取被删除行，RETURN OLD 允许原删除继续。归档与删除属于同一事务，删除失败时归档也撤销。

### 触发器 4：自动维护课程选课人数

已知课程表 Course(Cno, Cname, SelectedCount) 和选课表 SC(Sno, Cno, Grade)，
Course 的主键为 Cno，SC 的主键为 (Sno, Cno)，SC.Cno 是参照 Course.Cno 的外码。
SelectedCount 非空，初值与已有选课记录一致。本题只允许向 SC 插入或删除记录，
不允许修改 SC.Cno，也不直接修改 SelectedCount。编写行级触发器，使插入一条选课记录后
对应课程人数加 1，删除一条选课记录后人数减 1；一条语句处理多条记录时也应正确维护人数。

参考答案：

```sql
CREATE OR REPLACE FUNCTION maintain_selected_count()
RETURNS TRIGGER
LANGUAGE plpgsql
AS $$
BEGIN
    IF TG_OP = 'INSERT' THEN
        UPDATE Course
        SET SelectedCount = SelectedCount + 1
        WHERE Cno = NEW.Cno;
    ELSIF TG_OP = 'DELETE' THEN
        UPDATE Course
        SET SelectedCount = SelectedCount - 1
        WHERE Cno = OLD.Cno;
    END IF;
    RETURN NULL;
END;
$$;

CREATE TRIGGER sc_count_after_change
AFTER INSERT OR DELETE ON SC
FOR EACH ROW
EXECUTE FUNCTION maintain_selected_count();
```

TG_OP 表示当前触发事件；插入看 NEW，删除看 OLD。每影响一行就增减一次，多行操作也能维护人数。AFTER 触发器的返回值被忽略，因此可以 RETURN NULL。

### 触发器 5：语句级操作日志

已知员工表 Employee(Eid, Salary)，Eid 为主键；日志表 SalaryStatementLog(LogTime)
保存工资更新语句的执行时间。编写 AFTER UPDATE FOR EACH STATEMENT 触发器，
每条成功执行的 UPDATE 语句只向日志表插入一行。再分别说明一条 UPDATE 匹配 4 行和
匹配 0 行时会新增几条日志，以及若改为 FOR EACH ROW 时这两种情况各新增几条日志。
本题触发器不设置 WHEN 条件。

参考答案：

```sql
CREATE OR REPLACE FUNCTION log_salary_statement()
RETURNS TRIGGER
LANGUAGE plpgsql
AS $$
BEGIN
    INSERT INTO SalaryStatementLog(LogTime)
    VALUES (CURRENT_TIMESTAMP);
    RETURN NULL;
END;
$$;

CREATE TRIGGER employee_salary_statement
AFTER UPDATE ON Employee
FOR EACH STATEMENT
EXECUTE FUNCTION log_salary_statement();
```

语句级：UPDATE 匹配 4 行或 0 行，都新增 1 条日志。改为 FOR EACH ROW 后，分别新增 4 条、0 条日志。语句级触发器没有单行 NEW／OLD，本题只记录执行时间。

## 存储过程（5 道）

### 存储过程 1：输入、输出参数与条件分支

编写存储过程 classify_grade，输入参数 p_grade 为整数，输出参数 p_result 为文本。
当 p_grade 为 NULL 时返回“未录入”，不在 0～100 范围内时返回“成绩非法”，
90～100 返回“优秀”，60～89 返回“及格”，0～59 返回“不及格”。
使用 IF 分支给输出参数赋值，并写出传入 85 时的 CALL 调用语句。

参考答案：

```sql
CREATE OR REPLACE PROCEDURE classify_grade(
    IN p_grade INTEGER,
    OUT p_result TEXT
)
LANGUAGE plpgsql
AS $$
BEGIN
    IF p_grade IS NULL THEN
        p_result := '未录入';
    ELSIF p_grade < 0 OR p_grade > 100 THEN
        p_result := '成绩非法';
    ELSIF p_grade >= 90 THEN
        p_result := '优秀';
    ELSIF p_grade >= 60 THEN
        p_result := '及格';
    ELSE
        p_result := '不及格';
    END IF;
END;
$$;

CALL classify_grade(85, NULL);
```

输出 p_result 为“及格”。在普通 SQL 的 CALL 中，OUT 参数位置传 NULL 占位，调用结果会返回输出参数。

### 存储过程 2：按部门批量调薪

已知员工表 Employee(Eid, Ename, Deptno, Salary)，Eid 为主键，Deptno、Salary 均非空，
Salary 为非负数。编写存储过程 raise_salary，输入部门号 p_deptno 和加薪比例 p_rate，
输出实际更新人数 p_count。将指定部门每名员工的 Salary 更新为原工资乘以 (1 + p_rate)，
p_rate 为 NULL 或不在 0～0.5 范围内时抛出异常；部门没有员工时 p_count 返回 0。
使用一条 UPDATE 完成调薪，并让 p_count 取该语句实际影响的行数。

参考答案：

```sql
CREATE OR REPLACE PROCEDURE raise_salary(
    IN p_deptno Employee.Deptno%TYPE,
    IN p_rate NUMERIC,
    OUT p_count BIGINT
)
LANGUAGE plpgsql
AS $$
BEGIN
    IF p_rate IS NULL OR p_rate < 0 OR p_rate > 0.5 THEN
        RAISE EXCEPTION '加薪比例必须在 0～0.5 之间且不能为 NULL';
    END IF;

    UPDATE Employee
    SET Salary = Salary * (1 + p_rate)
    WHERE Deptno = p_deptno;
    GET DIAGNOSTICS p_count = ROW_COUNT;
END;
$$;

CALL raise_salary(10, 0.1, NULL);
```

示例假定部门号是整数 10；参数用 %TYPE 沿用表中字段类型。GET DIAGNOSTICS 紧接 UPDATE，读取影响行数；没有匹配员工时为 0。比例为 0 时，匹配的行仍计入影响行数。

### 存储过程 3：聚集查询与无记录处理

已知选课表 SC(Sno, Cno, Grade)，以 (Sno, Cno) 为主键，Grade 允许为 NULL。
编写存储过程 student_summary，输入学号 p_sno，输出已选课程数 p_total、
有成绩的课程数 p_graded 和平均成绩 p_avg。已选课程数包含 Grade 为 NULL 的记录，
平均成绩只计算非 NULL 成绩；没有选课记录时两个计数返回 0，平均成绩返回 NULL，
有选课但所有成绩均为 NULL 时，有成绩的课程数返回 0，平均成绩也返回 NULL。

参考答案：

```sql
CREATE OR REPLACE PROCEDURE student_summary(
    IN p_sno SC.Sno%TYPE,
    OUT p_total BIGINT,
    OUT p_graded BIGINT,
    OUT p_avg NUMERIC
)
LANGUAGE plpgsql
AS $$
BEGIN
    SELECT COUNT(*), COUNT(Grade), AVG(Grade)
    INTO p_total, p_graded, p_avg
    FROM SC
    WHERE Sno = p_sno;
END;
$$;

CALL student_summary('S1', NULL, NULL, NULL);
```

示例假定学号为文本 S1。COUNT(*) 数全部选课记录，COUNT(Grade) 只数非 NULL 成绩，AVG 忽略 NULL。没有 GROUP BY 的聚集查询即使没有匹配行，也返回一行：0、0、NULL；无需把平均值改成 0。

### 存储过程 4：循环、判断与批量插入

已知整数表 NumberResult(N, Kind)，N 为主键，Kind 保存“奇数”或“偶数”。
编写存储过程 fill_numbers，输入整数 p_n；当 p_n 为 NULL 或小于 1 时抛出异常，
否则先清空 NumberResult，再用循环依次插入 1 到 p_n，每行 Kind 根据 N 的奇偶性填写。
本题要求使用循环和条件分支，不使用 generate_series；调用成功后表中应恰好有 p_n 行。

参考答案：

```sql
CREATE OR REPLACE PROCEDURE fill_numbers(IN p_n INTEGER)
LANGUAGE plpgsql
AS $$
DECLARE
    v_i INTEGER;
    v_kind TEXT;
BEGIN
    IF p_n IS NULL OR p_n < 1 THEN
        RAISE EXCEPTION 'p_n 必须是大于等于 1 的整数';
    END IF;

    DELETE FROM NumberResult;
    FOR v_i IN 1..p_n LOOP
        IF v_i % 2 = 0 THEN
            v_kind := '偶数';
        ELSE
            v_kind := '奇数';
        END IF;
        INSERT INTO NumberResult(N, Kind) VALUES (v_i, v_kind);
    END LOOP;
END;
$$;

CALL fill_numbers(5);
```

先验证参数再清空表。调用后 N 为 1～5，Kind 依次为奇数、偶数、奇数、偶数、奇数；重复调用会重新生成。

### 存储过程 5：转账与异常处理（提高）

已知账户表 Account(Aid, Balance)，Aid 为主键，Balance 为非空、非负数。
编写存储过程 transfer_money，输入转出账户 p_from、转入账户 p_to 和金额 p_amount，
当任一参数为 NULL、两个账户相同、金额不大于 0、任一账户不存在或余额不足时抛出异常。
检查通过后，从转出账户扣款并向转入账户增加相同金额。两次更新必须处于同一事务中，
过程内部不执行 COMMIT，也不捕获并吞掉异常，保证失败时本次转账的修改全部撤销。
本题不考虑并发转账；写出在显式事务中从账户 1 向账户 2 转账 100 的调用语句。

参考答案：

```sql
CREATE OR REPLACE PROCEDURE transfer_money(
    IN p_from Account.Aid%TYPE,
    IN p_to Account.Aid%TYPE,
    IN p_amount NUMERIC
)
LANGUAGE plpgsql
AS $$
DECLARE
    v_balance Account.Balance%TYPE;
BEGIN
    IF p_from IS NULL OR p_to IS NULL OR p_amount IS NULL THEN
        RAISE EXCEPTION '账户和金额不能为 NULL';
    END IF;
    IF p_from = p_to THEN
        RAISE EXCEPTION '转出和转入账户不能相同';
    END IF;
    IF p_amount <= 0 THEN
        RAISE EXCEPTION '转账金额必须大于 0';
    END IF;

    SELECT Balance INTO v_balance FROM Account WHERE Aid = p_from;
    IF NOT FOUND THEN
        RAISE EXCEPTION '转出账户不存在';
    END IF;
    PERFORM 1 FROM Account WHERE Aid = p_to;
    IF NOT FOUND THEN
        RAISE EXCEPTION '转入账户不存在';
    END IF;
    IF v_balance < p_amount THEN
        RAISE EXCEPTION '转出账户余额不足';
    END IF;

    UPDATE Account SET Balance = Balance - p_amount WHERE Aid = p_from;
    UPDATE Account SET Balance = Balance + p_amount WHERE Aid = p_to;
END;
$$;

BEGIN;
CALL transfer_money(1, 2, 100);
COMMIT;
```

FOUND 必须在对应查询后立即检查。本题按要求不考虑并发；所有检查在扣款前完成，两次更新在调用者事务中执行。若 CALL 报错，当前事务进入失败状态，应执行 ROLLBACK，转账修改不会提交。
