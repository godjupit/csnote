## 1. 递归查询：查找全部先修课程（重点）

来源：参考书第 83～84 页习题 1（PDF 第 98～99 页），PPT 第 19～25 页；将多先修课情形整理为两张表。

课程表 Course(cno, cname) 保存课程编号和名称，cno 为主码；先修关系表 Prerequisite(cno, prereq_cno) 保存“课程 cno 的直接先修课为 prereq_cno”，两个编号共同作为主码并分别参照 Course。一门课程可以有多门直接先修课，也可以是多门课程的先修课。现有课程 C1～C6，名称分别为“程序设计基础”“数据结构”“数据库系统概论”“操作系统”“离散数学”“毕业设计”，先修记录为（C2，C1）、（C3，C2）、（C3，C4）、（C4，C1）、（C4，C5），C6 没有先修课，整个先修关系不存在环。请使用 WITH RECURSIVE 查询 C3 的全部直接和间接先修课程，显示课程编号（cno）与课程名称（cname），同一课程通过不同路径找到时只显示一次，不输出 C3 本身，并按课程编号升序排列；再说明初始查询、递归查询和终止条件分别是什么，以及为什么只连接固定次数不能适应任意层数的先修关系。


with recursive rs(n) as(
    select p_cno 
    from pre 
    where cno = 'c3'
    union 
    select p_cno
    from rs,pre
    where rs.n = pre.cno
)select cno
from course,rs
where rs.n = course.cno
order by course.cno;



## 2. 递归查询：补齐没有订单的日期（重点）

来源：PPT 第 28～29 页日期序列课堂练习，重新明确表结构与输出要求。

订单表 Orders(oid, odate, amount) 中，oid 为主码，odate 为 DATE 类型，amount 为非空 NUMERIC 类型，每行表示一笔订单。现有订单（1，2026-01-01，100）、（2，2026-01-01，50）、（3，2026-01-03，80）、（4，2026-01-05，120），没有其他订单。请使用 WITH RECURSIVE 生成 2026-01-01 至 2026-01-05 的完整日期序列，并统计每一天的订单数量和订单总金额，显示日期（d）、订单数量（order_count）和总金额（total_amount），没有订单的日期也必须显示，数量与金额均为 0，按日期升序排列。

with recursive rs(n) as(
    select date '2026-01-01'

    union 
    select n + 1
    from rs 
    where n < '2026-01-05'
)select sum(total_amount), count(oid), rs.n
from rs 
left join orders on rs.n = orders.odate
group by rs.n
order by rs.n


## 3. 过程化 SQL：变量、查询结果与游标（重点）

来源：PPT 第 37～57 页，围绕书第 83 页列出的过程化 SQL 与游标知识点自编。

已有选课表 SC(sno, cno, grade)，主码为（sno，cno），grade 可为空，非空值在 0～100 之间。现要处理三个任务：取得全表非空成绩的平均值；取得学生 S1 选修课程 C1 的课程号和成绩；逐行查看 S1 的全部选课记录，并对每门课程输出“及格”“不及格”或“未出成绩”。请分别说明每个查询可能返回几行、每行有几列，应如何接收或处理结果，为什么“返回两列”不等于“必须使用游标”，以及零行查询结果与返回一行 NULL 的结果有什么不同；再按课件格式写出一个过程化 SQL 匿名块，显式声明、打开、读取并关闭游标，完成第三个任务，成绩大于等于 60 判为及格，并用 RAISE NOTICE 输出课程号和状态。S1 没有选课记录时，程序应正常结束，不输出课程状态。

```
DECLARE
    CnoOfStudent CHAR(10);
    GradeOfStudent INT;

    mycursor CURSOR FOR
        SELECT Cno, Grade
        FROM SC
        WHERE Sno = 'S1';

BEGIN
    OPEN mycursor;

    LOOP
        FETCH mycursor
        INTO CnoOfStudent, GradeOfStudent;

        EXIT WHEN mycursor%NOTFOUND;

        IF GradeOfStudent IS NULL THEN
            RAISE NOTICE '课程 %：未出成绩', CnoOfStudent;
        ELSIF GradeOfStudent >= 60 THEN
            RAISE NOTICE '课程 %：及格', CnoOfStudent;
        ELSE
            RAISE NOTICE '课程 %：不及格', CnoOfStudent;
        END IF;
    END LOOP;

    CLOSE mycursor;
END;
```

## 4. 存储过程：使用游标统计成绩分布（重点）

来源：改编自书第 84～85 页习题 2①（PDF 第 99～100 页），对应 PPT 第 50～73 页。

已有 Course(cno, cname) 和 SC(sno, cno, grade)，Course 的主码为 cno，SC 的主码为（sno，cno），grade 可为空，非空值在 0～100 之间。请编写存储过程 course_grade_distribution，以课程编号 p_cno 为输入参数，显式使用游标逐行读取该课程的成绩，分别统计 [90,100]、[80,90)、[70,80)、[60,70)、[0,60) 五个分数段以及未出成绩的人数，并通过 RAISE NOTICE 输出六项统计结果。六个计数器初始值均为 0，不存在的课程应报告异常；课程存在但没有选课记录时，六项统计均输出 0。写出存储过程定义，并给出查询课程 C1 成绩分布的调用语句。

### 参考答案（课件格式）

读这道题时，抓住“传入课程号 → 游标逐个读成绩 → 对应计数器加一 → 输出统计”这条执行顺序。

```sql
CREATE OR REPLACE PROCEDURE course_grade_distribution(
    IN p_cno CHAR(10)
)
AS
DECLARE
    course_count INT;
    student_grade INT;

    count_a INT := 0;
    count_b INT := 0;
    count_c INT := 0;
    count_d INT := 0;
    count_e INT := 0;
    count_null INT := 0;

    mycursor CURSOR FOR
        SELECT Grade
        FROM SC
        WHERE Cno = p_cno;
BEGIN
    /* 课程不存在与课程没有选课记录，是两种情况 */
    SELECT COUNT(*) INTO course_count
    FROM Course
    WHERE Cno = p_cno;

    IF course_count = 0 THEN
        RAISE EXCEPTION '课程不存在';
    END IF;

    OPEN mycursor;

    LOOP
        FETCH mycursor INTO student_grade;
        EXIT WHEN mycursor%NOTFOUND;

        IF student_grade IS NULL THEN
            count_null := count_null + 1;
        ELSIF student_grade >= 90 THEN
            count_a := count_a + 1;
        ELSIF student_grade >= 80 THEN
            count_b := count_b + 1;
        ELSIF student_grade >= 70 THEN
            count_c := count_c + 1;
        ELSIF student_grade >= 60 THEN
            count_d := count_d + 1;
        ELSE
            count_e := count_e + 1;
        END IF;
    END LOOP;

    CLOSE mycursor;

    RAISE NOTICE
        '90～100：%，80～89：%，70～79：%，60～69：%，不及格：%，未出成绩：%',
        count_a, count_b, count_c,
        count_d, count_e, count_null;
END;
```

调用：

```sql
CALL course_grade_distribution('C1');
```

开卷时认这几个位置：

| 写法 | 作用 |
| --- | --- |
| IN p_cno | 接收要统计的课程号 |
| count_a INT := 0 | 声明计数器并初始化 |
| WHERE Cno = p_cno | 筛选这门课程的选课记录 |
| FETCH ... INTO student_grade | 每次取一行的成绩 |
| mycursor%NOTFOUND | 本次没取到行，结束循环 |
| count_a := count_a + 1 | 对应分数段的人数加一 |
| RAISE NOTICE | 输出统计结果 |

IF / ELSIF 从上往下判断，命中一个分支后就不再进入其他分支，所以 85 分只会进入 count_b。NULL 要单独判断；课程存在但没有人选时，第一次 FETCH 就没有记录，六个计数器仍是 0。

## 5. 存储函数：将百分制成绩转换成等级（重点）

来源：改编自书第 84～86 页习题 2③（PDF 第 99～101 页），对应 PPT 第 76～78 页；改为返回等级，保留原始成绩。

已有 SC(sno, cno, grade)，主码为（sno，cno），grade 为可空整数。请编写返回 TEXT 的存储函数（按课件格式） grade_level(p_grade INT)，将 90～100 分转换为 A、80～89 分转换为 B、70～79 分转换为 C、60～69 分转换为 D、0～59 分转换为 E，输入 NULL 时返回 NULL，输入小于 0 或大于 100 的分数时报告异常。再在一条 SELECT 中调用该函数，显示每条选课记录的学号、课程号、原始成绩和等级，按学号、课程号升序排列，不修改 SC 中的 grade；最后说明该任务为什么适合使用函数，以及存储函数与存储过程在返回值声明和调用方式上有什么区别。

### 参考答案（课件格式）

这个任务输入一个成绩、返回一个等级，适合写成函数，再在 SELECT 的表达式中调用。

```sql
CREATE OR REPLACE FUNCTION grade_level(p_grade INT)
RETURNS TEXT
AS
BEGIN
    IF p_grade IS NULL THEN
        RETURN NULL;
    ELSIF p_grade < 0 OR p_grade > 100 THEN
        RAISE EXCEPTION '成绩必须在 0～100 之间';
    ELSIF p_grade >= 90 THEN
        RETURN 'A';
    ELSIF p_grade >= 80 THEN
        RETURN 'B';
    ELSIF p_grade >= 70 THEN
        RETURN 'C';
    ELSIF p_grade >= 60 THEN
        RETURN 'D';
    ELSE
        RETURN 'E';
    END IF;
END;
```

在查询中调用：

```sql
SELECT sno, cno, grade,
       grade_level(grade) AS level
FROM SC
ORDER BY sno, cno;
```

例如，grade 为 85 时，grade_level(grade) 返回 B；grade 为 NULL 时返回 NULL。SELECT 只是显示等级，不会修改原来的 grade。

| 对比 | 存储过程 | 存储函数 |
| --- | --- | --- |
| 定义的开头 | CREATE ... PROCEDURE | CREATE ... FUNCTION |
| 返回类型 | 不使用函数的 RETURNS 子句；可通过 OUT / INOUT 参数传出结果 | 必须声明返回类型，这里是 RETURNS TEXT |
| 本组题的调用方式 | CALL 过程名(...) | SELECT 函数名(...)，或放在 SELECT 表达式中 |
| 例子 | 执行工资调整、输出成绩统计 | 把一个分数转换成一个等级 |

不要把“过程不能返回结果”当成结论：过程可以用 OUT / INOUT 参数传出结果。区别在于这里的函数可以直接作为查询表达式使用。

## 6. 存储过程：按参数调整工资

来源：改编自书第 92 页补充习题 2①b（PDF 第 107 页），对应 PPT 第 59～73 页。

员工表 Employee(eid, ename, salary) 以 eid 为主码，salary 为非空 NUMERIC 类型且不能小于 0。请编写存储过程 raise_low_salary，以工资标准 p_threshold 为输入参数，把工资低于该标准的员工工资统一调整为该标准，等于或高于标准的员工保持不变。参数为 NULL 或小于 0 时应报告异常，标准为 0 时允许正常执行，没有员工需要调整时也应正常结束。写出过程定义及按标准 8000 调用的语句，并说明这个批量更新是否必须逐行使用游标。

### 参考答案（课件格式）

```sql
CREATE OR REPLACE PROCEDURE raise_low_salary(
    IN p_threshold NUMERIC
)
AS
BEGIN
    IF p_threshold IS NULL OR p_threshold < 0 THEN
        RAISE EXCEPTION '工资标准不能为空，也不能小于 0';
    END IF;

    UPDATE Employee
    SET salary = p_threshold
    WHERE salary < p_threshold;
END;
```

调用：

```sql
CALL raise_low_salary(8000);
```

执行后的变化：

| 原工资 | 调用后的工资 |
| --- | --- |
| 6000 | 8000 |
| 8000 | 8000 |
| 10000 | 10000 |

本题不需要游标。UPDATE 本身就能一次处理所有符合条件的记录，没有必要逐行 FETCH。没有符合条件的员工时，更新 0 行，正常结束；标准为 0 时也允许执行。只有需要按行处理结果、且题目要求使用游标时，才套用游标循环的写法。

## 7. JDBC：参数化查询与结果集处理

来源：依据书第 88～91 页习题 4 的 JDBC 数据访问题型（PDF 第 103～106 页）和 PPT 第 93～103 页自编，缩小为单数据库查询。

已有 Employee(eid, ename, salary)，eid 为主码，ename 与 salary 非空。请编写一个 Java 方法，连接参数作为方法参数传入，使用 JDBC 和 PreparedStatement 查询工资大于等于给定标准 minSalary 的员工，显示员工编号、姓名和工资，并按工资降序、员工编号升序输出；不要把 minSalary 直接拼接到 SQL 字符串中。查询没有返回记录时应正常结束，连接、语句和结果集资源在正常结束或抛出异常时都必须释放。请在代码中体现建立连接、设置参数、执行查询、遍历结果集和释放资源的过程，并说明 ResultSet.next() 的作用以及本题应使用 executeQuery 还是 executeUpdate。

### 参考答案

JDBC 按“连接 → 创建语句 → 设置参数 → 执行查询 → 逐行取结果 → 关闭资源”的顺序阅读。代码使用标准 JDBC 接口，数据库连接信息由调用者传入。

```java
import java.math.BigDecimal;
import java.sql.Connection;
import java.sql.DriverManager;
import java.sql.PreparedStatement;
import java.sql.ResultSet;
import java.sql.SQLException;

public class EmployeeQuery {
    public static void printEmployees(
            String url,
            String user,
            String password,
            BigDecimal minSalary) throws SQLException {

        if (minSalary == null) {
            throw new IllegalArgumentException("工资标准不能为空");
        }

        String sql =
            "SELECT eid, ename, salary FROM Employee " +
            "WHERE salary >= ? " +
            "ORDER BY salary DESC, eid ASC";

        try (Connection conn =
                 DriverManager.getConnection(url, user, password);
             PreparedStatement stmt = conn.prepareStatement(sql)) {

            // 第一个 ? 的位置编号为 1
            stmt.setBigDecimal(1, minSalary);

            try (ResultSet rs = stmt.executeQuery()) {
                while (rs.next()) {
                    String eid = rs.getString("eid");
                    String name = rs.getString("ename");
                    BigDecimal salary = rs.getBigDecimal("salary");

                    System.out.println(
                        eid + " " + name + " " + salary
                    );
                }
            }
        }
    }
}
```

这段代码使用 try-with-resources 自动释放资源，正常结束或抛出异常都会执行关闭；关闭顺序为 ResultSet、PreparedStatement、Connection。运行时需要提供对应数据库的 JDBC 驱动。

| 写法 | 认识它的作用 |
| --- | --- |
| DriverManager.getConnection(...) | 建立数据库连接 |
| conn.prepareStatement(sql) | 创建带参数的语句对象 |
| WHERE salary >= ? | 用问号占位，工资值不直接拼入 SQL |
| stmt.setBigDecimal(1, minSalary) | 把工资标准绑定到第一个问号 |
| stmt.executeQuery() | 执行 SELECT，取得结果集 |
| rs.next() | 移动到下一行；存在该行时返回 true |
| rs.getString("ename") | 取得当前行的姓名 |
| rs.getBigDecimal("salary") | 取得当前行的工资 |

ResultSet 一开始位于第一行之前，所以先调用 next()，再读取列值；如果查询没有结果，第一次 next() 就返回 false，循环不会执行。

本题用 executeQuery，因为需要取得 SELECT 返回的结果集。INSERT、UPDATE、DELETE 通常用 executeUpdate，它返回受影响的行数。

### 开卷速查

| 遇到的任务 | 优先想到的写法 |
| --- | --- |
| 查询结果只有一行 | SELECT ... INTO 变量 |
| 按题意逐行取结果并处理 | 声明游标 → OPEN → FETCH → 判断结束 → CLOSE |
| 保存一段可重复调用的操作 | CREATE PROCEDURE，使用 CALL 调用 |
| 计算一个值并放进 SELECT | CREATE FUNCTION，声明 RETURNS，使用 RETURN |
| 把所有满足条件的记录统一更新 | UPDATE ... WHERE，不必逐行循环 |
| Java 中查询数据 | PreparedStatement → 设置参数 → executeQuery → ResultSet.next |
