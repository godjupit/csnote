### 关系代数运算

#### 1. 除运算

至少使用了与供应商S1 所供应的全部零件相同零件代码的工程项目代码JNO。

用到除运算，就是找到与另外一个关系中所有元素都有对应关系的元素

`R(JNO,PNO)\ S(PNO)`

左边有两列：JNO、PNO，右边只有一列：PNO。除运算的结果就是左边剩余的那一列 JNO。
含义就是左边jno所有含有右边pno的元素

#### 2. 自然连接

#### 4. 操作对象和结果

#### 5. 主属性与非主属性

关系模型中,非主属性不可能出现在任何候选码中。 是正确的，因为候选码中的都是主属性

#### 6. 左外连接

在左外连接中,保留的是左边关系中所有的元组。

#### 7. 三类完整性约束

关系模型的三类完整性约束：用户定义的完整性，参照完整性，实体完整性

#### 8. 参照关系与被参照关系

谁持有外码，谁就是参照关系；谁的主码被引用，谁就是被参照关系。

外码就是一张表应用另外一张表的主码

#### 9. 投影与连接

投影是从关系中取出列并去重

- 自然连接要求两个关系的同名属性都相等，去掉相同的属性列
- 等值连接只要求 `S.C=T.C`，保留两个关系的全部属性列

### 存取控制

- 将用户权限登陆到数据字典中
- 合法权限检查
- 权限由数据库对象和操作类型共同决定

#### 自主存取控制

是一种有授权资格的用户管理和转授权限的存取控制方式

`GRANT` 和 `REVOKE` 进行控制。

**CASCADE：**

cascade会撤销掉所有依赖这里的权限，会沿着授权链级联撤销 U5、U6、U7 从这条链获得的权限

假设 U7 同时从其他独立授权来源获得了 INSERT 权限，即使 U5 这条授权链被撤销，U7 仍可以保留来自其他来源的权限。

**RESTRICT：**

RESTRICT 的意思是“限制撤销”：如果某项权限已经被继续授予其他用户，撤销它会影响下游授权，那么数据库就拒绝执行这次撤销操作。
其中，DBA 授予 U1 查询权限并允许转授，U1 又授予 U2，U2 再授予 U3。使用restrict
数据库发现 U2 和 U3 的权限依赖于 U1，因此整条撤销语句执行失败。结果是 U1、U2、U3 原有的权限都保持不变。

## 第五章 数据库完整性

数据库的完整性防止存在不符合语义的数据，防止数据库存在不存在的数据

### 实体完整性

- create table用主键定义
- 有列级约束和表级约束
- 单属性的主键可以用两种，多属性只能用后一种
- 主码值唯一并且不能为空

### 参照完整性

- foreign key：那些码是外码
- reference：指定这些外码参照那些主码

#### 外码与主码的关系

| 对比 | 主码 PRIMARY KEY | 外码 FOREIGN KEY |
| --- | --- | --- |
| 主要作用 | 唯一标识一条记录 | 建立表与表之间的参照关系 |
| 是否允许重复 | 不允许 | 允许 |
| 是否允许 NULL | 不允许 | 可以允许 |
| 定义方式 | PRIMARY KEY | FOREIGN KEY ... REFERENCES |

```sql
FOREIGN KEY (Sno) REFERENCES Student(Sno),
/*在表级定义参照完整性，Sno是外码，被参照表是Student */
FOREIGN KEY (Cno) REFERENCES Course(Cno)
/*在表级定义参照完整性，Cno是外码，被参照表是Course */
```

### 用户定义完整性

针对某一具体应用的数据必须满足的语义要求

RDBMS提供了定义和检验这类完整性的机制，不必由应用程序承担

#### 属性上的约束

CREATE TABLE中定义属性上的约束

- 列值非空（NOT NULL）
- 列值唯一（UNIQUE）
- 检查列值是否满足一个条件表达式（CHECK短语）

#### 元组上的约束

约束一行的属性
元组约束可以限制同一行中的多个属性。例如，要求学生的最低成绩不能高于最高成绩：

```sql
CREATE TABLE Student (
    Sno CHAR(8) PRIMARY KEY,
    MinGrade INT,
    MaxGrade INT,

    CHECK (MinGrade <= MaxGrade)
);
```

这里 CHECK (MinGrade <= MaxGrade) 同时涉及两个属性，所以属于元组级约束。

要求生成 2026-01-01 到 2026-01-10 的完整日期序列，并统计每天的订单数量和总金额。即使某一天没有订单，也必须出现在结果中，统计值为 0。

```sql
with recursive rs(date) as(
    select '2026-01-01'

left rs join o_date on rs.date = o_date.odate;
```

left join语法不正确，然后就是union的问题

**修正后：**

```sql
WITH RECURSIVE rs(d) AS (
    SELECT DATE '2026-01-01'

    UNION ALL

    SELECT d + 1
    FROM rs
    WHERE d < DATE '2026-01-10'
)
SELECT rs.d, o.oid, o.odate, o.amount
FROM rs
LEFT JOIN orders o ON rs.d = o.odate
group by rs.d
order by rs.d;
```

**注意 UNION ALL 和 UNION：**

- UNION：合并结果，并去除重复行。
- UNION ALL：合并结果，不去重，通常可以避免去重开销。

#### 部门及其子部门的员工总数

题目：使用递归 SQL 统计部门及其所有子部门的员工总数部门表数据如下：

| id | name | parent_id | level | employee_count |
| --- | --- | --- | --- | --- |
| 1 | 总公司 | NULL | 1 | 100 |
| 2 | 技术中心 | 1 | 2 | 60 |
| 3 | 市场中心 | 1 | 2 | 25 |
| 4 | 后端开发部 | 2 | 3 | 30 |
| 5 | 前端开发部 | 2 | 3 | 20 |
| 6 | 测试部 | 2 | 3 | 10 |
| 7 | 数字营销部 | 3 | 3 | 15 |
| 8 | 品牌推广部 | 3 | 3 | 10 |
| 9 | Java开发组 | 4 | 4 | 15 |
| 10 | Python开发组 | 4 | 4 | 15 |

编写一条 SQL 查询，使用 WITH RECURSIVE 递归公用表表达式，计算每个部门及其所有层级子部门的员工总数。

```sql
with recursive rs(root_id, id) as(
    select id, id
    from department
    union
    select root_id, id
    from rs
    left join department d rs.root_id = d.root.id;
)SELECT rs.root_id, SUM(d.employee_count)
FROM rs
JOIN department d ON rs.id = d.id
GROUP BY rs.root_id;
```

重点就是保留一个rootid每次都可以在找rootid一样的，

### 过程化 SQL

#### 游标

过程化sql如何只返回了一个数可以将它赋值给一个变量，但是如果返回多个变量就需要

```sql
DO $$
DECLARE
    course_no INT;
    student_grade INT;

    cur CURSOR FOR
        SELECT Cno, Grade
        FROM SC
        WHERE Sno = '20180001';
BEGIN
    OPEN cur;

    LOOP
        FETCH cur INTO course_no, student_grade;

        EXIT WHEN NOT FOUND;

        IF student_grade >= 60 THEN
            RAISE NOTICE '课程 %：及格', course_no;
        ELSE
            RAISE NOTICE '课程 %：不及格', course_no;
        END IF;
    END LOOP;

    CLOSE cur;
END;
$$;
```

```sql
cur CURSOR FOR
    SELECT Cno, Grade
    FROM SC
    WHERE Sno = '20180001'
```

声明一个叫 `cur` 的游标。

`OPEN cur`：打开游标。

```sql
FETCH cur INTO course_no, student_grade;
```

将游标的值去除赋值给两个变量

#### 存储过程

存储过程的代码：

```sql
CREATE OR REPLACE PROCEDURE check_grade(
    IN student_grade INT,
    OUT result TEXT
)
LANGUAGE plpgsql
AS $$
BEGIN
    IF student_grade >= 60 THEN
        result := '及格';
    ELSE
        result := '不及格';
    END IF;
END;
$$;
```

所以，存储过程的重点并不是它能进行什么特殊运算，而是把一系列数据库操作和控制逻辑封装成可重复调用的程序，并且在数据库服务器内部执行。

`CREATE PROCEDURE` 创建的是保存程序逻辑的数据库对象。
